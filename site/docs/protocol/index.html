Mermoz JSON-RPC protocol (mermozd)

This is the protocol between Mermoz's daemon, mermozd, and its clients: the Mac app, the mermoz CLI and the MCP server. Use it to build your own client; for agents, the CLI and the MCP server are simpler. Source: docs/protocol.md.

mermozd is the only process that touches the network and the database. The app, the CLI and the MCP server are clients of this protocol.

Transport

  • Unix domain socket at $MERMOZ_HOME/mermozd.sock. MERMOZ_HOME defaults to ~/Library/Application Support/Mermoz; MERMOZ_SOCKET overrides the socket path (macOS limits it to 104 bytes).
  • JSON-RPC 2.0, one JSON object per line (\n terminated), UTF-8.
  • Requests are answered in order per connection. A connection that called subscribe additionally receives notifications (no id) at any time.

Conventions

  • Timestamps: integer Unix milliseconds.
  • Dates without time (due dates): "YYYY-MM-DD".
  • Priority: 0 none, 1 urgent, 2 high, 3 normal, 4 low.
  • Status keys: unread (entry status), then for read mail todo, waiting, in_progress, backlog, review (an agent draft awaits approval), done, archive, deleted (Gmail Trash). done, archive and deleted are out of the inbox. Reading an unread thread moves it to the open status new mail interrupted, else the router's suggestion, else todo; new mail from someone else brings it back to unread.
  • Projects are the user's Gmail labels, identified by name (nested with /). A thread can be in several.
  • Thread number is a stable human id like "M-1287"; every method taking a thread id also accepts its number.

Errors

code name meaning
-32601 method_not_found
-32602 invalid_params message says which param and why
-32004 not_found unknown thread / draft / account / attachment
-32010 approval_required send moved to Review; data: {draft, thread}
-32011 app_only method only callable from Mermoz.app
-32020 upstream provider (Gmail) error; data: {status, body}

Google Drive

Drive has its own consent and refresh token per account (stored apart from the Gmail one), so declining or disconnecting Drive never affects mail. Asked scopes: drive.readonly (read any file the user can open: previews, files shared with a thread's people, search) and drive.file (files Mermoz created or the user picked: saving attachments, sharing a picked file). Google lets the user untick either; drive.status says what was granted.

Send gate

Attach is an absolute file path, or {"path" | "from_attachment" | "url", "filename"?, "inline"?}: from_attachment copies an attachment of a message already in Mermoz (forwarding), url adds a link listed under the text instead of a file. Files are copied into blobs/drafts/<draft>/ and deleted once the draft is sent or deleted. Each Draft has attachments: [{id, kind: "file"|"link", filename, mime, size, path?, url?, inline}]. More than 25 MB of files in one draft is refused with a plain-words message. Messages larger than 4 MB go through Gmail's upload endpoint.

drafts.send sends immediately when the caller is Mermoz.app, or when agents_may_send is true. Otherwise the draft moves to state review, its thread to status review, and the call fails with approval_required:

{"code": -32010, "message": "approval_required: draft dft_8f2c is waiting for the user to approve it in Mermoz. Tell the user; do not retry.",
 "data": {"draft": "dft_8f2c", "thread": "M-1262"}}

The caller is Mermoz.app when the peer process's executable (from the socket's peer pid) lives inside a bundle named Mermoz.app. review.* and settings.set are refused with app_only for any other caller.

chat_delta carries the whole visible answer so far (never the actions block), at most every 60 ms while chat.send streams; the final answer is chat.send's result. A Claude turn paused by its web search loop (pause_turn) is resumed automatically, up to 3 times, into the same answer; past that, the answer so far is kept.
